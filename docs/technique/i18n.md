# Traductions (i18n)

**Source unique :** [shared/i18n/](../../shared/i18n/), un fichier `<langue>.json` par langue au format **ICU MessageFormat**. Le français (`fr.json`) est la langue source : toute nouvelle clé y est ajoutée d'abord.

```bash
pnpm --dir shared build:i18n            # génère les fichiers des apps et liste les traductions manquantes
pnpm --dir shared build:i18n --strict   # échoue s'il en manque une (CI de release)
```

| Espace de noms | Contenu | Utilisé par |
|---|---|---|
| `common` | Actions, états, unités, nom de l'offre Plus | les trois apps |
| `errors` | Un message par `code` d'erreur de l'API ([conventions](conventions-api.md#erreurs--applicationproblemjson-rfc-9457)) | les trois apps |
| `app` | Interface du mobile | mobile |
| `web` | Site public | web |
| `admin` | Back-office | admin |

| Sortie | Format |
|---|---|
| `mobile/lib/core/l10n/arb/app_<langue>.arb` | ARB pour `flutter gen-l10n` (`mobile/l10n.yaml`). Clés en camelCase (`app.meal.analyses_left` devient `appMealAnalysesLeft`), variables typées |
| `web/messages/<langue>.json`, `admin/messages/<langue>.json` | JSON imbriqué pour `next-intl` |

## Conventions de clés
- Format `espace.écran.élément[.variante]`, en `snake_case`. Exemple : `app.meal.analyses_left`.
- Une clé par sens, pas par écran : on réutilise `common.action.save` au lieu de dupliquer.
- Les erreurs portent le nom du `code` de l'API : `errors.quota_exceeded`.

## Messages
- Sous-ensemble ICU autorisé :
  - `{prenom}` ;
  - `{n, number}` ;
  - `{n, plural, =0 {…} one {# …} other {# …}}` ;
  - `{type, select, a {…} other {…}}`.
- **Pas de date ni d'heure dans les messages** : le client les formate avec `intl` dans la langue de l'utilisateur, puis les passe en texte. Le build refuse les autres formes.
- Pas de concaténation de morceaux de phrases dans le code : une phrase entière par clé.
- Les pluriels suivent les règles CLDR de chaque langue. L'arabe a six formes : il faut les fournir dans `ar.json`.
- Le tutoiement est utilisé partout en français.

## Contrôles du build
- Tous les messages sont du ICU valide.
- Chaque traduction a exactement les mêmes variables que le français.
- Aucune clé n'existe dans une langue sans exister en français.
- Les clés manquantes sont signalées. À l'exécution, l'ordre de repli est : langue de l'utilisateur, puis anglais, puis français.

## Ce qui n'est pas dans ce catalogue
Les **contenus** (recettes, plantes, exercices, conseils, notifications, FAQ, pages légales) sont traduits dans l'admin et renvoyés déjà traduits par l'API (`Accept-Language`).
